How Hindsight supports the product

Memory is part of the repeat-booking workflow.

1RetainAfter a completed job, retain the coordinator-approved site condition and outcome with a source booking ID.
2RecallOn a repeat booking, query relevant history by service category and site ID.
3Reflect with sourcesSummarize prior context and show source facts. The coordinator checks whether they still apply.
4Keep assignment deterministicMemory never overrides verification, availability, rating, distance, or coordinator review.
Current Hindsight status is shown at the top of the page. When the Hindsight server is unavailable, the prototype labels local fallback records as demo memory.

Hackathon demo walkthrough

  1. Choose Construction / Kompally and load the synthetic prior-job memory.
  2. Recall site history. Show the note and its booking source beside the new job.
  3. Book a scheduled tile-work job for three workers. Show the nearest eligible assignment and 30% advance calculation.
  4. Complete the job with a new operational note. Explain that this note is retained for a future repeat booking.
  5. Recall again. Contrast the before/after context, while explaining that Hindsight does not decide who gets assigned.

For the official demo, connect the app to Hindsight before recording so the memory trace reflects real retain/recall calls.
